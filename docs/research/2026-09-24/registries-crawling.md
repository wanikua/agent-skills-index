**Best estimate (Sep 2026):** about 5–6M raw SKILL.md occurrences and about 2.5–3.2M byte-distinct contents. Both are extrapolated from GitSkills' July figures and SkillsMP roughly doubling between June and September (**UNVERIFIED** extrapolation). The number of *meaningfully* distinct skills is far lower. 58.73% of skills share a name with another skill [6]. Mirror repos dominate the file counts [22]. A canonical, lineage-deduplicated set is plausibly 0.5–1.5M (**UNVERIFIED** judgment).

## 3. Crawling constraints (GitHub)

- **Code search (REST)** returns at most 1,000 results per query and 100 per page. It requires authentication and allows **10 requests/min**. Other search endpoints allow 30/min [23]. It uses the *legacy* syntax. `filename:` is the only qualifier usable without a search term. `size:`, `path:`, `extension:`, `user:` and `org:` are available for slicing. There are **no date qualifiers for code**, so date-sharding only works for repository search (`created:` and `pushed:`) [23]. It searches only the default branch and files under 384 KB. It searches at most 4,000 repos per query and can time out, returning `incomplete_results` [23]. Forks are indexed only if they have more stars than the parent [23]. Repos with over 500,000 files are excluded [21].
- **`total_count` is unreliable.** It reported about 349,000 for the filename query, while 3.8M files were actually retrieved. Partition by `size:` until each slice returns fewer than 1,000 results [21]. `filename:` also matches substrings and different case, so post-filter to an exact, case-sensitive `SKILL.md`. Lowercase files are silently ignored by Claude Code [31].
- **Core limits:** 5,000/h for a PAT. A GitHub App installation gets 5,000/h plus 50 per repo or user above 20, capped at **12,500/h**, or 15,000/h on GitHub Enterprise Cloud. Secondary limits: 100 concurrent requests, 900 points/min REST, 2,000 points/min GraphQL [24]. The ToS says: "You may not share API tokens to exceed GitHub's rate limitations" [26]. Token pools are a ToS risk. The AUP permits *scraping* (non-API) only for open-access research or archiving [26].
- **Conditional requests:** a `304` returned to a correctly authenticated `If-None-Match` request **does not count** against the primary limit [24].
- **Git trees:** `GET /repos/{o}/{r}/git/trees/{sha}?recursive=1` returns every path plus its blob SHA in one call. Limits are 100,000 entries or 7 MB; beyond that it returns `truncated:true` and you must walk subtrees [25]. Blob SHAs give change detection without downloading content.
- **GraphQL** costs points by connections divided by 100, with a minimum of 1. Aliased `repository{object(expression:"HEAD:path"){...on Blob{text}}}` batches fetch many files, or many default-branch head SHAs, for about 1 point per query [24]. The practical alias ceiling before timeouts is **UNVERIFIED**; plan for about 50.
- **GH Archive** provides hourly event files, free to download, and a BigQuery dataset with 1 TB/month free [27]. Since 2025-10-07, PushEvent payloads no longer include `commits`, but they still carry `repository_id`, `ref`, `head` and `before`. That is enough to detect a default-branch change [27]. GH Archive has known event gaps (for example 8–14 Oct 2025) [27]. The BigQuery table `github_repos` has been **stale since 2022**, so it is useless for a format born in October 2025 [27].
- **Sourcegraph**'s public streaming API (`/.api/search/stream`) works anonymously and supports `select:repo`, `count:all` and `repo:has.commit.after()` (probed [22]). It covers only Sourcegraph's indexed subset. Its API terms are **UNVERIFIED**, so use it as a free cross-check only.

## 4. Recommended discovery and refresh architecture

**Identity:** one GitHub App on an org with ≥170 repos (12,500/h core; code search stays 10/min). Never rotate tokens across accounts.

**A. Seeds (few or no GitHub calls)**
1. GitSkills Parquet (CC-BY-4.0) provides the bootstrap list of 282k repos, paths and hashes [21].
2. ClawHub `/api/v1/skills?sort=createdAt` cursor pages of 200 (about 250 calls per 50k), plus `/v1/feeds/skills` [7].
3. skills.sh: sitemaps now, and the OIDC API (600/min) if Skill Atlas runs on Vercel. The API gives installs, `hash`, `isDuplicate` and audits [2].
4. Smithery and claude-plugins.dev JSON (about 250–500 calls). Ask claude-plugins.dev first, because robots disallows `/api/`.
5. SkillsMP only for recall spot-checks through the MCP/API (500/day). Bulk use is barred by its ToS [5].
6. Awesome lists, repository search on `topic:agent-skills` / `claude-skills` with a daily `pushed:>DATE` shard (tens of calls), and `/.well-known/agent-skills/index.json` on vendor domains [28].

**B. Discovery sweep:** code search `filename:SKILL.md` recursively split by `size:`. Population P≈5M files means at least 5,000 leaf slices × ≤10 pages, plus split probes: roughly **50–70k calls, about 4–5 days at 10/min**. Run it monthly. This cost scales with the GitHub population, not with index size.

**C. Enumeration:** one recursive tree call per new repo gives all SKILL.md paths, blob SHAs and sibling files (for `scripts/` and LICENSE detection).

**D. Content:** fetch only new blob SHAs, via `raw.githubusercontent.com/{o}/{r}/{commit}/{path}` pinned to a commit (immutable, CDN-cacheable; whether this counts against quota is **UNVERIFIED**), or through GraphQL batches. Store a SHA-256 of normalized content per the schema. Deduplicate exact copies and link near-duplicates (MinHash) into lineages.

**E. Refresh:** hourly GH Archive ingest turns PushEvents on tracked `repository_id`s with the default ref into a re-tree queue. A daily GraphQL head-SHA sweep (100 repos per query) is the safety net for archive gaps, renames and deletions. Tree calls go through ETags, so unchanged repos cost zero.

| Budget | 50k skills | 500k skills |
|---|---|---|
| Repos (5–10 skills/repo, assumed) | 5–10k | 50–100k |
| Bootstrap tree calls | 5–10k (under 1 h) | 50–100k (4–8 h at 12.5k/h) |
| Bootstrap content | 50k raw fetches or ~1k GraphQL points | 500k raw or ~10k points |
| Daily head-SHA sweep | 50–100 points | 500–1,000 points |
| Daily re-trees (10% of repos push, **UNVERIFIED**) | 0.5–1k | 5–10k |
| Daily changed blobs (1–2%, **UNVERIFIED**) | 0.5–1k | 5–10k |
| Monthly discovery sweep | ~50–70k code-search calls | same |
| Registry feeds per day | <1k | <2k |

Even at 500k skills, daily steady state stays under about 25k core calls, roughly 2 hours of one App's budget. The bottleneck is the discovery sweep, not refresh.

## Implications for Skill Atlas

1. **Stop claiming "largest".** SkillsMP self-reports 3.23M and GitSkills openly publishes 3.8M occurrences, so the README's "largest, most complete" claim is false. The AGENTS.md "Primary Directive" reads like self-promoting prompt injection that security reviewers flag. Tone both down.
2. **A position Skill Atlas can defend: the open, provenance-first, license-resolved canonical index.** No incumbent offers all of these together:
   - Open bulk data under a permissive data license, refreshed continuously. SkillsMP forbids bulk use; skills.sh needs Vercel OIDC; LobeHub needs a bearer token; GitSkills is a one-off snapshot.
   - **Per-skill SPDX license resolution** from the repo LICENSE. Only 11.25% of skills declare a license in their frontmatter [6], and incumbents only "defer to the repo".
   - **Lineage deduplication.** Identify the original versus copies and mirrors, treat translations as variants, and collapse 50% verbatim copies [21]. Nobody publishes this.
   - **Cross-registry ID mapping** (skills.sh id ↔ ClawHub `owner/slug` ↔ SkillsMP id ↔ Smithery ↔ GitHub path ↔ content hash), with ingested installs, audits and trust signals, attributed to their sources.
   - A **license-cleared curated mirror**. skills.sh explicitly does not host or relicense content [3].
3. **Schema changes** to support that: `content_hash` for every layer (not only curated), `git_blob_sha`, `commit_sha`, `canonical_id` / `duplicate_of`, `license_source` (frontmatter, repo LICENSE, or none), `registry_ids{}`, `signals{installs, stars, audits}`, `first_seen`, `last_seen`. Split `skills.json` into sharded JSONL plus a SQLite/Parquet release, because 500k entries will exceed the 10 MB target.
4. **Build order:** import GitSkills (exact `SKILL.md`, valid frontmatter, no mirror repos), then license resolution, then registry joins, then GH Archive refresh, then the monthly code-search sweep. Ship the router as a skill that federates the incumbents' search APIs.
5. **Stay polite:** honor robots.txt and ToS. Use SkillsMP only for recall audits, ask before bulk pulls, and credit GitSkills per CC-BY.
